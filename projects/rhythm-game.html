LONG NOTE

롱노트 점수 처리

유지 중 점수와 콤보를 추가하고, 종료 허용 구간에서 같은 결과를 얻도록 보완했습니다.

1-1유지 중 점수 누적

참고한 프로젝트는 롱노트를 누를 때와 뗄 때 점수를 반영했습니다. 누르고 있는 동안에도 점수와 콤보가 증가하도록 BPM에 맞춰 반복 실행하는 코루틴을 추가했습니다.

LongNotePress()에서 시작 판정, 노트의 시작과 종료 시각을 저장한 뒤 IELongEffect()를 실행합니다. 시작 판정이 NICE이면 NICE 횟수와 콤보를 늘리고, GOOD이면 GOOD 횟수를 늘리며 콤보를 초기화합니다. 처리할 때마다 다음 판정 시각을 waitTime만큼 옮깁니다.

Judgement.cs C#

IELongEffect()의 반복 구간입니다. 점수를 반영하고 longTimeCountStart를 다음 처리 시각으로 이동시킨 뒤 다음 반복을 기다립니다.

while ( longTimeCountStart[line] < longTimeCount[line] )
{
    if ( judgeType == JudgeType.NICE )
    {
        score.data.nice++;
        score.data.judge = JudgeType.NICE;
        score.data.combo++;
    }
    else if ( judgeType == JudgeType.GOOD )
    {
        score.data.good++;
        score.data.judge = JudgeType.GOOD;
        score.data.combo = 0;
    }
    score.SetScore();
    hitEffectPool.ShowHitEffect(line);
    longTimeCountStart[line] += waitTime * 1000f ;

    if (longTimeCountStart[line] > longTimeCount[line])
        score.SetAccuracy();

    yield return new WaitForSeconds( waitTime );
}

1-2종료 허용 구간의 남은 판정 반영

정상적인 종료 허용 구간에서 손을 떼어도 코루틴 실행 횟수가 적으면 점수와 콤보가 낮아졌습니다. 종료 시 남은 판정 횟수를 반영해 NICE로 시작한 롱노트가 끝까지 누른 경우와 같은 점수와 콤보를 얻도록 수정했습니다.

CheckLongNote()는 종료까지 남은 시간이 0ms 이상 150ms 미만인 경우, longTimeCountStart부터 longTimeCount까지 남은 횟수를 셉니다. 시작 판정이 NICE이면 NICE 횟수와 콤보에, GOOD이면 GOOD 횟수에 반영하고 콤보를 초기화합니다.

NICE 한 번당 500점과 콤보 1개를 반영합니다. 종료보다 150ms를 초과해 일찍 떼면 MISS로 처리하며, 짧은, 중간, 긴 롱노트를 배치해 종료 시점에 따른 점수와 콤보를 확인했습니다.

Judgement.cs C#

종료 허용 구간에 들어왔을 때 실행하는 부분입니다. 아직 처리하지 않은 횟수만 계산하고 시작 판정에 따라 점수와 콤보에 반영합니다.

while ( longTimeCountStart[line] < longTimeCount[line] )
{
    longComboCount[line] += 1;
    longTimeCountStart[line] += waitTime * 1000f;
}
if ( longJudge[line] == JudgeType.NICE )
{
    score.data.nice += longComboCount[line];
    score.data.combo += longComboCount[line];
}
else
{
    score.data.good += longComboCount[line];
    score.data.combo = 0;
}

AUDIO / TIMING

FMOD 연동

음악 재생 위치를 판정과 노트 위치 보정의 공통 기준으로 연결했습니다.

2-1판정과 노트 위치

AudioSource로 같은 곡을 반복해서 플레이할 때 판정 타이밍이 다르게 느껴져 FMOD를 적용했습니다. 음악 재생과 시간 조회를 FMOD 채널에 연결한 뒤, 직접 플레이했을 때 타이밍이 나아졌다고 느꼈습니다.

MusicPlayer.cs의 GetMilliSec()로 재생 위치를 읽고 사용자 싱크 설정을 반영한 뒤 노트 시각과 비교합니다. 오차의 절댓값이 75ms 미만이면 NICE, 75ms 이상 150ms 미만이면 GOOD으로 판정합니다.

화면의 노트는 Time.deltaTime으로 이동하되, 생성이나 배속 변경 시 음악 시간과 노트 시각의 차이에 싱크 설정과 배속을 반영해 위치를 다시 계산합니다. 이 판정과 이동 구조는 참고 프로젝트를 활용했고, 음악 재생과 시간 조회 부분을 FMOD에 연결했습니다.

FMOD 채널의 재생 위치를 밀리초 단위로 반환합니다. 판정 코드에서는 이 값에서 사용자 Sync 설정을 빼 공통 시간 기준으로 사용합니다.

public float GetMilliSec()
{
    musicChannel.getPosition(out uint pos, FMOD.TIMEUNIT.MS);
    return pos;
}

2-2배경 영상

음악은 FMOD, 영상은 VideoPlayer로 분리하고 영상 오디오는 껐습니다. 재생, 일시정지, 재개를 함께 처리하고, 재생 위치를 설정할 때는 ms를 초로 변환해 영상에도 반영했습니다.

채보 에디터에서도 음악과 영상의 재생과 정지 상태를 함께 확인하며 노트를 배치할 수 있도록 연결했습니다.

MusicPlayer.cs C#

일시정지, 재개, 정지 요청이 들어오면 FMOD 음악 채널과 VideoPlayer를 함께 제어합니다. 재생 상태도 같은 함수에서 갱신해 편집 화면의 재생 제어와 연결했습니다.

public void Pause()
{
    state = State.Paused;
    musicChannel.setPaused(true);
    videoPlayer.Pause();
}

public void UnPause()
{
    state = State.Unpaused;
    musicChannel.setPaused(false);
    videoPlayer.Play();
}

public void Stop()
{
    state = State.Stop;
    musicChannel.stop();
    videoPlayer.Stop();
}

CUSTOMIZATION

커스터마이징

테마를 한 번에 적용하거나 라인별로 세밀하게 조합할 수 있도록 두 가지 설정 방식을 제공했습니다.

3-1테마와 라인별 선택 데이터

라인마다 노트를 꾸미고 싶은 사용자와 간단하게 설정을 끝내고 싶은 사용자를 함께 고려했습니다. 테마 전체 적용과 상세 설정을 제공하고 기어, 라인별 노트, 캐릭터, 판정선, 이펙트, 타격음 등을 조정하도록 구성했습니다.

테마와 노트 데이터는 ScriptableObject인 CustomDataSO를 공통 기반으로 만들었습니다. ThemeData에는 NotesData가 포함되고, NotesData에는 네 라인의 LineData가 연결됩니다. 상속으로 공통 식별 정보를 공유하고, 참조로 테마 구성을 조합했습니다. PlayerCustomize가 선택값을 보관하며 테마 선택과 개별 설정이 이 값을 함께 변경합니다.

RECORDS / SAVE

플레이 기록 저장

곡, 난이도, 모드별 기록을 데이터로 묶고, 갱신된 결과가 있을 때 저장했습니다.

4-1기록 데이터와 저장 방식

처음에는 곡과 난이도별 결과를 PlayerPrefs의 문자열로 저장하려 했습니다. 모드와 기록 항목이 늘어날 때의 관리를 고려해 PlayRecord로 데이터를 묶고 JSON 파일에 저장하도록 구성했습니다.

기록은 songId, difficulty, gameMode 조합으로 구분합니다. 최고 점수, 최대 콤보, 최고 정확도를 항목별로 갱신하며, 새 기록이나 갱신된 값이 있을 때 RecordRepository가 records.json에 저장합니다.

일반 모드와 댄스 모드에 같은 구조를 사용하고, 음량과 커스터마이징 선택값처럼 간단한 설정은 PlayerPrefs에 저장합니다. JSON 저장을 구현할 때는 ChatGPT의 도움을 받았습니다.

개선할 점

  • 롱노트의 반복 점수 처리는 WaitForSeconds를 사용해 프레임 간격에 영향을 받습니다. 낮은 FPS에서 긴 롱노트의 처리 횟수를 확인할 필요가 있습니다.
